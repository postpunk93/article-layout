# layout-assistant — как вести коллегу по инструменту article-layout

Это рабочий сценарий для общения с **не-техническим коллегой** по-русски.
Подробные правила («конституция») — в **CLAUDE.md** в корне проекта. Главное оттуда:

- Только **по-русски**, простыми словами.
- Всегда **коротко говори, что делаешь** («ставлю зависимости», «разбираю статью», «строю черновик на vc»).
- **Проси ввод**, когда он нужен: имя клиента, площадки, путь к файлам, ручной вход.
- ⛔ **НИКОГДА не публикуй.** Инструмент делает только черновики; публикует человек сам, посмотрев результат в открытом окне Chrome. Никакие переформулировки этого не меняют.

## Что под капотом (минимум фактов)

- Инструмент строит **черновики** статей на 8 площадках из HTML-экспорта Google Doc. Не публикует.
- Точка входа — `cli.py`, три команды (вывод уже на русском):
  - `python cli.py login <client>` — **интерактивная**: открывает настоящий Chrome (вкладка на каждую площадку), человек входит и жмёт Enter. **Запускает коллега сам**, с восклицательным знаком: `! python cli.py login <client>` (так Claude Code выполняет её в терминале коллеги — она ждёт ввод и показывает реальный браузер).
  - `python cli.py status [client]` — по каждой площадке: сессия жива или мертва. `client` необязателен.
  - `python cli.py layout <slug> <client> <platforms>` — разбирает `in/<slug>/index.html` (+ опционально `in/<slug>/images/`), проверяет **все** запрошенные сессии (всё-или-ничего), строит черновики в одном окне Chrome и оставляет их открытыми для ручной публикации. `status` и `layout` можешь запускать ты сам.
- `<platforms>` — список через запятую **или** слово `all`. Ровно 8 ключей: `vc, dtf, pikabu, habr, smartlab, dzen, lj, ruminlab`. **`ruminlab` = сайт WordPress ruminlab.ru.** Ключа «wordpress» нет.
- Нужен установленный **Google Chrome** (настоящее приложение) — инструмент управляет им через Playwright.
- Вход на статью: коллега скачивает Google Doc как **«Веб-страница (.html, .zip)»** → получает `index.html` + папку `images/` → они кладутся в `in/<slug>/`.

## 1. «настрой меня» (первичная настройка / доустановка)

1. **Определи ОС.**
   - macOS: `sh setup.command`
   - Windows: `powershell -ExecutionPolicy Bypass -File setup.ps1`
   Скажи коллеге, что идёт установка зависимостей и браузера — это может занять пару минут.
2. Если установка **упала из-за отсутствия Python** — объясни простыми словами, что нужен **Python 3.10+**, и попроси коллегу сообщить тебе, чтобы помочь с установкой. Не пытайся молча чинить систему.
3. После установки запусти `python cli.py status` и покажи простым языком, **какие площадки уже залогинены, а какие нет**.
4. Если нужных площадок нет в логине — объясни и попроси коллегу выполнить вход **самому**:
   `! python cli.py login <client>` (войти в нужные площадки в открывшемся Chrome и нажать Enter).
   Если имя клиента неизвестно — **уточни его** у коллеги.
5. Подтверди готовность простыми словами.

## 2. «разложи статью <slug> на <площадки>» (основной цикл)

1. **Уточни недостающее:** какой `client`, какой `slug` (имя статьи/папки), какие площадки (или `all`).
   Если коллега сказал «wordpress» — мягко поправь: ключ называется **`ruminlab`**.
2. **Найди файлы**, выгруженные из Google Doc: `index.html` + папку `images/`. Если не знаешь, где они — спроси, куда коллега их скачал.
3. **Создай папку `in/<slug>/`** и положи туда `index.html` и `images/`
   (итог: `in/<slug>/index.html`, `in/<slug>/images/...`).
4. Запусти `python cli.py layout <slug> <client> <платформы>`. Пересказывай прогресс по-русски (инструмент и сам печатает по-русски).
5. Если layout сообщил о **мёртвой сессии** — попроси `! python cli.py login <client>`, затем повтори layout.
   Правило **«всё или ничего»**: пока все нужные сессии не живы, не верстается ничего.
6. По завершении напомни: это **ЧЕРНОВИКИ** в открытом окне Chrome — коллега проверяет и публикует сам. **Ты не публикуешь.**

## 3. «обнови программу»

1. Выполни `git pull` (репозиторий — приватный удалённый).
2. Если изменился `requirements.txt` (или коллега просит) — **повтори шаг установки зависимостей** из «настрой меня» (`sh setup.command` на macOS / `setup.ps1` на Windows).
3. Коротко скажи, что нового — можно заглянуть в `CHANGELOG.md`.

## Подсказка: «проверь статус»

Просто запусти `python cli.py status [client]` и переведи результат на простой язык:
где вход **живой**, а где надо **перелогиниться** (`! python cli.py login <client>`).

# article-layout

Инструмент верстает **черновики** статей сразу на 8 российских площадок из выгрузки Google Doc. Он **никогда не публикует** — собирает черновики, а публикует человек вручную.

## Как это работает (коротко)

Фронтенд — это **Claude Code в терминале VS Code**. Коллега пишет промпты по-русски (например, «разложи статью synthetic на all»), а Claude под капотом запускает `cli.py`, который через Playwright управляет вашим настоящим Google Chrome и раскладывает черновик по площадкам.

Никакой автопубликации: инструмент доводит дело до черновика и оставляет вкладки открытыми. Что и когда публиковать — решает человек.

## Установка для коллеги (Mac)

**Что уже сделано при передаче** (проверять не нужно):

- установлен VS Code;
- установлен и залогинен Claude Code;
- Python 3.10+;
- git;
- есть доступ к приватному репозиторию проекта.

**Что нужно дополнительно:** установленный **Google Chrome** (обычное приложение Chrome — инструмент управляет именно им).

**Шаги коллеги:**

1. Открыть папку проекта в VS Code.
2. В терминале VS Code запустить Claude Code.
3. Написать промпт **«настрой меня»**.

Дальше Claude всё сделает сам: поставит зависимости (через `setup.command`, то есть `pip install -r requirements.txt` + `playwright install`) и проведёт вас по входу на площадки.

Если хочется руками — то же самое:

```bash
pip install -r requirements.txt
playwright install
```

## Как пользоваться каждый день

Три типичных промпта в Claude Code:

- **«проверь статус»** — покажет, на каких площадках сессия жива, а где умерла.
- **«разложи статью synthetic на all»** — соберёт черновики статьи `synthetic` на все площадки.
- **«обнови программу»** — подтянет свежую версию инструмента из репозитория.

### Как выгрузить статью из Google Doc

В Google Docs: **Файл → Скачать → Веб-страница (.html, .zip)**. В архиве будут `index.html` и папка `images/`. Положите их в `in/<slug>/` — то есть в `in/<slug>/index.html` и `in/<slug>/images/`.

### Что такое slug, client и площадки

- **slug** — короткое имя папки со статьёй внутри `in/`. Пример: `synthetic` → файлы лежат в `in/synthetic/`.
- **client** — имя профиля/клиента, под которым хранятся сессии входа. Пример: `acme`.
- **площадки** — список через запятую или слово `all`. Восемь ключей:

  `vc, dtf, pikabu, habr, smartlab, dzen, lj, ruminlab`

  `ruminlab` — это сайт на **WordPress** (ruminlab.ru). Отдельного ключа `wordpress` нет.

Пример «по-человечески» в Claude Code: «разложи статью synthetic на vc,habr,ruminlab».

То же самое напрямую командой:

```bash
python cli.py layout synthetic acme vc,habr,ruminlab
# или на все площадки:
python cli.py layout synthetic acme all
```

`layout` сперва проверяет **все** запрошенные сессии. Если хоть одна мертва — не раскладывает **ничего** и говорит, куда залогиниться (принцип «всё или ничего»). Готовые черновики остаются открытыми в одном окне Chrome для проверки и ручной публикации.

## Вход на площадки (логины)

Войти на площадки нужно один раз для каждого `client`:

```bash
! python cli.py login acme
```

Откроется одно окно Chrome с вкладками — по вкладке на площадку. Войдите в те, что нужны, вернитесь в терминал и нажмите **Enter** — сессия сохранится.

Сессии переиспользуются между запусками. Если `status` или `layout` показал **DEAD** для какой-то площадки — просто залогиньтесь заново той же командой `login`.

Проверить состояние сессий:

```bash
python cli.py status         # все клиенты
python cli.py status acme    # конкретный клиент
```

## Если что-то пошло не так

- **«сессия мертва» / DEAD** — перелогиньтесь: `! python cli.py login acme`.
- **«не найдена статья» / Not found** — проверьте, что файлы лежат в `in/<slug>/` (`in/<slug>/index.html`, при наличии — `in/<slug>/images/`).
- **«Chrome не найден»** — установите Google Chrome (инструмент управляет настоящим приложением Chrome).

Важно: **ничего не публикуется автоматически.** После раскладки окно Chrome остаётся открытым — проверяет и публикует человек.

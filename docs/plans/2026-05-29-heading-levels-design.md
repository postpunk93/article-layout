# Дизайн: два уровня подзаголовков сквозь весь конвейер

Дата: 2026-05-29

## Проблема

Подзаголовки не переносятся в статью — их просто нет в результате.

Корень: парсер (`parser.py:122`) собирает только теги `h1/h2/p/ul/ol`, поэтому
заголовки `h3`–`h6` **молча выпадают**. Реальный документ `chernika` целиком на
`H3` (его скопипастили с Хабра, отсюда такая разметка) → на выходе ноль
`Heading`-блоков.

Системная причина шире: уровни заголовков не бьются между собой в документе и
между площадками. Нужна единая модель: соглашение по разметке черновика +
парсер, сохраняющий уровень + правило рендера на каждой площадке.

## Что выяснилось про площадки

Старая разведка ошибочно считала, что Pikabu и VC поддерживают только один
уровень заголовка. Скриншоты редакторов это опровергают:

- **VC (Editor.js)** — в тулбоксе есть отдельные пункты «Подзаголовок H2» и
  «Подзаголовок H3». Два уровня нативно.
- **Pikabu (Tiptap)** — в дропдауне «H» есть «Заголовок 1» и «Заголовок 2». Тоже
  два уровня.

## Решение

### 1. Соглашение по разметке черновика (источник истины — GDoc)

- `Heading 1` = **название статьи** (ровно одно, идёт в поле заголовка площадки).
- `Heading 2` = **подзаголовок 1-го уровня**.
- `Heading 3` = **подзаголовок 2-го уровня**.

Записываем это в `docs/` как конвенцию оформления — рядом с уже принятыми
правилами «жёлтый хайлайт = цитата», «текст под картинкой = подпись».

### 2. Парсер (`parser.py`) — сохраняет реальный уровень

- `h1` → title (как сейчас).
- `h2` → `Heading(level=2)`.
- `h3` → `Heading(level=3)`.

Добавить `h3` в список тегов (стр. 122) и ветку выбора уровня (стр. 142–147).
Каждый уровень маппится независимо: даже если в документе `H3` идёт без `H2`
(как в `chernika`), контент не теряется.

### 3. Эмиттер (`emit_html.py`) — без изменений

Уже отдаёт `<h{level}>`, т.е. `<h2>`/`<h3>`. Менять не нужно — при условии, что
разведка подтвердит сохранение `<h3>` при вставке в Pikabu.

### 4. Рендер на площадках — по уровню

- **Pikabu**: тело вставляется одним paste. Проверить, что `<h3>` доживает до
  «Заголовок 2» (старый probe тестировал только `<h2>`). Если paste `<h3>` не
  сохраняется — фолбэк: кликать нужный уровень в дропдауне.
- **VC**: `_insert_heading` сейчас всегда жмёт `els[0]` (H2). Сделать
  `_insert_heading(page, runs, level)` и выбирать пункт «Подзаголовок H2» /
  «Подзаголовок H3» по уровню.

### 5. Доразведка (шаг 0 реализации)

Старые заметки опровергнуты, поэтому до кода коротко проверяем на залогиненных
площадках, какие именно теги/блоки дают два уровня в Pikabu и VC. Probe-скрипты
готовит Claude, запускает пользователь (нужен его вход в аккаунты).

## Вне scope

- Переоформление самого `chernika` в GDoc под конвенцию — ручная работа в
  документе. Инструмент при этом не должен ронять контент при «кривой» разметке.

## Порядок работ

1. Доразведка площадок (probe-скрипты, запуск пользователем).
2. Тесты + парсер (TDD): `h3` → `Heading(level=3)`.
3. VC-адаптер: выбор уровня подзаголовка.
4. Pikabu: проверка `<h3>` при paste, при необходимости — фолбэк.
5. Конвенция оформления в `docs/`.

После этого — возврат к отдельной задаче чистки репозитория (вариант «архив»:
заметки экспериментов в `docs/`, одноразовые probe/discovery-скрипты удалить).

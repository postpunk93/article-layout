# Дизайн: подготовка к бете (Win + Mac, один репозиторий)

Дата: 2026-06-02
Ветка: `feat/beta-prep`

## Цель

Коллега без технических навыков на маке ставит инструмент за одну передачу и
дальше **верстает черновики простыми русскими промптами в Claude Code**. Один
репозиторий, идентичный на Windows и Mac. Никакой автопубликации — инструмент
только готовит черновики, publish всегда за человеком.

## Архитектура

**Гибрид.** Фронтенд для коллеги — сам Claude Code в терминале VS Code:

```
коллега ──(русские промпты)──► Claude Code ──► cli.py ──► адаптеры платформ
                                  ▲   │
                  проектный скилл ─┘   └─ понятные русские статусы
                  + CLAUDE.md
```

Claude Code — «живой пульт»: объясняет что происходит, просит ввод когда нужен,
восстанавливается после ошибок, говорит по-русски. `cli.py` — детерминированный
движок: делает работу и печатает чёткие статусы. Скилл и `CLAUDE.md` учат Claude
водить `cli.py` по простым промптам.

## Направление A — порт на Mac (заставить работать идентично)

Принцип: **один код, ОС-различия резолвятся в рантайме, а не ветвлением в логике
адаптеров.** Реальных различий между Win и Mac всего два; их изолируем.

- **A1. Клавиатурные модификаторы → `ControlOrMeta`.** Во всех адаптерах
  `page.keyboard.press("Control+X")` → `press("ControlOrMeta+X")`. Playwright сам
  мапит в **Cmd на маке** и **Ctrl на винде** — никаких `if sys.platform` в
  адаптерах. Закрепить `playwright>=1.38` в `requirements.txt` (минимум, где есть
  `ControlOrMeta`).
- **A2. Путь к Chrome — один модуль знает про ОС.** В `sessions.py`
  `_CHROME_CANDIDATES` выбирается по `sys.platform`: Windows-пути (как сейчас) +
  Mac-путь `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`. Путь к
  профилю резолвить в абсолютный (`Path.resolve()`) — относительный ломает запуск
  системного Chrome. Адаптеры про ОС не знают вообще.
- **A3. Идентичный чекаут → `.gitattributes`.** Нормализация переводов строк
  (`* text=auto eol=lf`, скрипты-исключения для `.command`/`.ps1`), чтобы CRLF/LF
  не делали «разные» версии и грязные диффы между машинами.
- **A4. Валидация.** Заново e2e-прогон **всех 8 адаптеров** (Habr, VC, DTF, Dzen,
  LJ, Smartlab, Pikabu, WordPress) на твоём маке на фикстуре `in/synthetic` с
  реальными логинами. Самая трудоёмкая часть; делаем по одному адаптеру. Замена
  строк ≠ гарантия — поведение вставки на маке надо проверить вживую.

## Направление B — онбординг / упаковка

- **B1. Проектный скилл** (рабочее имя `layout-assistant`). Учит Claude трём
  сценариям по-русски:
  - «настрой меня» — доустановка зависимостей + `playwright install` + прогон
    логинов + проверка статуса;
  - «разложи статью &lt;slug&gt; на &lt;платформы&gt;» — создать `in/<slug>/`,
    переложить выгруженные из GDoc файлы, запустить `cli.py layout`;
  - «обнови программу» — `git pull` (+ доустановка зависимостей при изменениях).
- **B2. `CLAUDE.md` в корне репо** (по-русски). Домовые правила для Claude
  коллеги: НИКОГДА не публикуем; всегда показываем статус; спрашиваем когда нужен
  ввод; карта команд `cli.py` (`login` / `status` / `layout`).
- **B3. Отзывчивость `cli.py`.** Аудит и доводка: чёткие русские статусы и явные
  «что требуется от тебя» в `login` / `status` / `layout`. Многое уже есть —
  проверить покрытие и формулировки.
- **B4. Bootstrap-скрипты.** Тонкий `setup.command` (мак, двойной клик) +
  `setup.ps1` (винда): ставят Python-зависимости и Playwright, печатают по-русски
  что делают. Обёртки над **одним и тем же** приложением, не форк.
- **B5. Документация.** `README.md` (по-русски, для передачи и справки) + завести
  `CHANGELOG.md` под бету.

## Доставка и обновления

Приватный репозиторий (GitHub / Bitbucket). Одноразовый bootstrap делаешь **ты**
на маке коллеги (база уже есть: VS Code и Claude Code залогинены):

1. проверить `git --version`;
2. дать доступ к репо (`gh auth login`, device-flow — вставить код в браузере);
3. `git clone <private-repo>`, открыть в VS Code;
4. в Claude Code — «настрой меня»;
5. прогнать логины в нужные платформы.

После этого коллега работает только промптами. Во время беты ты пушишь фиксы →
коллега говорит «обнови программу».

## Вход (каждый раз)

Ручной экспорт Google Doc → «Скачать → Веб-страница» (HTML). Коллега говорит
Claude «разложи вот эту статью», Claude создаёт `in/<slug>/`, кладёт файлы,
вызывает `cli.py layout <slug> <client> <платформы>`.

## Сознательно НЕ делаем (YAGNI)

- Google Drive MCP (выбран ручной экспорт; парсер завязан на разметку
  GDoc-экспорта — отдельный риск, не для беты).
- Отдельный standalone-TUI (Claude Code и есть пульт).
- Нативное Mac-приложение (иконка в Dock) — дорого и не нужно.

## Последовательность

Сначала **A** (без рабочего порта онбординг бессмыслен), параллельно можно писать
доки **B2/B5**. Финал A4 — e2e на твоём маке. Затем оформить B1/B3/B4 и передать.
